# ADR 0012：上下文预算与伙伴槽位

> 状态：已采纳
> 日期：2026-11-26
> 背景：用户为协作与上下文定了硬约束：伙伴最多 2 个（3 路并行）、模型窗口 1M、消息 800K、system 200K、输出 128K；伙伴可单独选脑子和模型，支持主智能体指派、用户自选、临时改。

## 1. 上下文预算

按「1M 是输入窗口」实现：

| 预算 | 值 | 说明 |
|---|---|---|
| 输入窗口 | 1,000,000 tokens | 主智能体一次请求的输入上限 |
| 消息预算 | 800,000 tokens | 对话历史 + 工具结果；超出触发压缩 |
| system 预算 | 200,000 tokens | Brain 提示词 + 项目记忆；超出直接截断，不多用 |
| 最大输出 | 128,000 tokens | 所有 provider 统一 `max_tokens` |

实现落点：

- `brain-prompt.ts`：system 超过 200K token（按 chars/4 估算约 800K 字符）截断，并标注「已截断」。
- `context-manager`：`modelContextLimit` 默认 800K，压缩在消息预算内进行。
- `openai.ts`：请求体带 `max_tokens: 128000`；provider 配置可覆盖。
- 模型能力不足 1M 时：按模型实际 contextWindow 降级，UI 标注「该模型窗口小于 1M，预算已按实际值缩放」。

**如果后续确认 1M 包含输出**：消息预算降为 672K（1000K − 200K − 128K）。这是一个配置项，改动只涉及两个常量。

## 2. 伙伴槽位

每个会话固定 **2 个伙伴槽位**，加主智能体 = **3 路并行**。

```ts
interface PartnerConfig {
  slot: 1 | 2;
  brainId: string;
  /** 不填则用主会话当前模型 */
  model?: ModelSelection;
}
```

规则：

- 最多 2 个槽位；第 3 个伙伴直接拒绝。
- 每个槽位独立选择 Brain 与模型，互不影响。
- 主智能体可以：
  - 按槽位咨询：`consult_partner({ slot: 1, question })`
  - 临时指派：`consult_partner({ brainId: 'codex', model: 'gpt-6', question })`（不改槽位，单次生效）
- 用户可以：
  - 在输入区/设置页配置两个槽位（脑子 + 模型）
  - 对话中临时改槽位，下一轮生效
- 伙伴的模型选择通过 `ModelRequest.selection` 传给 gateway，不走主会话模型。

## 3. 三种配置方式

| 方式 | 入口 | 作用域 |
|---|---|---|
| 主智能体指派 | `consult_partner` 的 `slot` / `brainId` / `model` | 单次调用 |
| 用户自选 | 输入区伙伴槽位、设置页 | 会话级 |
| 临时改 | 对话中直接改槽位 | 会话级，下一轮生效 |

优先级：单次调用参数 > 槽位配置 > 主会话默认。

## 4. UI

- 输入区：两个伙伴槽位（可折叠），每个显示 `脑子 / 模型`。
- 设置页新增「伙伴」分区：两个槽位的脑子与模型选择。
- 消息流：伙伴卡片标题显示 `伙伴 1 · Profession / glm-5`，标明槽位与模型。

## 5. 与主智能体的关系

- 主智能体始终用主会话的 Brain 与模型（不受伙伴槽位影响）。
- 伙伴只读，不能写文件、不能跑命令。
- 伙伴共享完整对话历史（用户要求），但 system 用伙伴自己的 Brain。
- 伙伴的调用计入会话成本；每个槽位独立计数。

## 6. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| P5.1 | 上下文预算（1M/800K/200K/128K） | 超长 system 被截断；请求带 max_tokens 128K |
| P5.2 | `PartnerConfig` 协议 + 服务端槽位存储 | 能设置/读取 2 个槽位；第 3 个拒绝 |
| P5.3 | `consult_partner` 支持 slot/brainId/model | 按槽位选脑子与模型；临时指派不改槽位 |
| P5.4 | UI：输入区槽位、设置页伙伴分区 | 可配置、可临时改、卡片显示槽位与模型 |

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 1M 窗口模型不普及 | 按模型能力降级，UI 标注实际预算 |
| 128K 输出模型不支持 | provider 按模型能力 clamp，记录实际值 |
| 伙伴槽位与主会话模型冲突 | 单次参数 > 槽位 > 主会话，显式优先级 |
| 两个伙伴同时咨询导致成本翻倍 | 槽位独立计数 + 会话总预算提示 |
