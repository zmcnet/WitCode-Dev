# WitCode 视觉验收清单

适用阶段：P1（左侧会话列表 + 消息流 + 工具调用卡片）
维护人：Visual-1
基线：`apps/web/src/App.tsx`、`apps/web/src/styles.css`（评审见 `review-001.md`）

## 使用方法

- 每条以 `- [ ]` 开头，验收通过改为 `- [x]` 并记录日期/浏览器/视口。
- `[自]` = 可由 `playwright.spec.ts` 自动断言；`[手]` = 需要人工目视确认。
- 三档基准视口：**桌面 1440×900**、**笔记本 1280×800**、**窄屏 768×1024**。
- 任何 P0 项不通过即阻塞进入下一阶段；P1 不通过需登记到本文件末尾的「遗留问题」。

---

## 1. 布局与响应式

- [ ] [手] 桌面 1440×900：左侧会话列表、中间消息流、右侧/底部输入区三区边界清晰，无重叠、无横向滚动条。
- [ ] [手] 桌面 1440×900：消息流区在内容变长时独立滚动，头部与输入区保持固定不随内容移动。
- [ ] [手] 笔记本 1280×800：左侧栏可折叠或保持合理宽度（建议 240–280px），消息区仍有足够阅读宽度。
- [ ] [手] 笔记本 1280×800：长消息与长工具结果不撑破容器，不产生页面级横向滚动。
- [ ] [手] 窄屏 768×1024：侧栏收起为抽屉/图标入口，有明确开关，且开关有可读名称。
- [ ] [手] 窄屏 768×1024：气泡最大宽度随视口收缩（不固定 86% 导致过窄或溢出）。
- [ ] [手] 三档视口下：输入区始终可见，不被虚拟键盘/窗口缩放遮挡。
- [ ] [自] 768 视口下：`document.documentElement.scrollWidth <= clientWidth`（无横向溢出）。
- [ ] [手] 三档视口下：留白、对齐、分隔线位置一致，无跨档位的错位跳变。

## 2. 空态

- [ ] [手] 首次进入（无会话、无消息）：展示欢迎标题、说明文案与明确下一步引导（可点击的入口，而非纯文字提示）。
- [ ] [手] 无会话态：会话列表区展示空态插画/文案与「新建会话」入口，而非空白区域。
- [ ] [手] 有会话但无消息：消息区展示该会话的轻量空态，输入区仍可用。
- [ ] [手] 空态文案无错别字、中英混排空格合理、语气一致。
- [ ] [自] 空态下页面标题为 `WitCode`，且不存在 assistant 气泡。
- [ ] [手] 空态在 1440 / 1280 / 768 三档均垂直居中或视觉平衡，不贴顶/贴底。

## 3. 流式输出

- [ ] [手] 逐字输出：文本按 chunk 增量追加，非一次性整体出现。
- [ ] [手] 光标：生成中在文本末尾显示闪烁光标；`done` 后光标立即消失。
- [ ] [手] 长文本：正常换行，超长单词/URL 不溢出气泡（需 `overflow-wrap: anywhere` 与 `min-width: 0` 验证）。
- [ ] [手] 代码块：围栏代码渲染为独立代码块，等宽字体、保留缩进、有横向滚动、有复制按钮。
- [ ] [手] 代码块在窄屏 768 下不撑破气泡，复制按钮可点。
- [ ] [手] 流式过程中消息区自动滚动跟随最新内容；用户手动上滚后不被强制拉回（需滚动锁定逻辑）。
- [ ] [手] 多个会话切换时，旧会话的流式状态不串台、光标不残留。

## 4. 连接与发送状态

- [ ] [手] 连接中：有明确的「连接中」文案/指示（当前缺失，见 review-001 P0-02）。
- [ ] [手] 已连接：状态点/文字为成功态，且发送按钮可用。
- [ ] [手] 断开：状态为断开态（红色 + 文案，不能仅靠颜色），发送按钮禁用且给出原因提示。
- [ ] [手] 重连：断线后自动重连或提供「重新连接」按钮，恢复后状态回到「已连接」。
- [ ] [自] 断开后状态文本变为「未连接」。
- [ ] [手] 发送中：按钮变为「生成中…」并禁用，Enter 重复触发不会产生第二条请求。
- [ ] [手] 可发送：按钮文案为「发送」，输入非空且已连接时高亮。
- [ ] [手] 输入为空时按 Enter 不发送、不报错、无视觉抖动。

## 5. 错误态

- [ ] [手] 模型报错：错误以独立、可辨识的样式展示（图标/标签/颜色），不是普通 assistant 气泡。
- [ ] [手] 网络断开：已有消息保留不丢失，状态栏明确提示，并可恢复。
- [ ] [手] 后端 500：`error` 消息展示可读信息而非原始堆栈；提供重试入口。
- [ ] [手] 错误发生后 `busy` 正确复位，发送按钮恢复可用，不残留闪烁光标。
- [ ] [手] 畸形/未知服务端消息不会使界面崩溃（解析有保护）。
- [ ] [手] 错误文案在 1440 / 768 下均可见、不被截断。

## 6. 工具调用卡片

- [ ] [手] 调用中：卡片显示工具名 + 进行中态（spinner），参数可折叠预览。
- [ ] [手] 成功：卡片有成功标识，结果与调用同一卡片内关联展示。
- [ ] [手] 失败：卡片有失败标识与错误摘要，颜色/图标与成功态可区分（不依赖颜色单一维度）。
- [ ] [手] 长参数：JSON 参数超长时折叠 + 展开，展开区可滚动，不撑破气泡。
- [ ] [手] 长结果：结果区有最大高度 + 内部滚动，默认收起，提供「查看全部」。
- [ ] [手] 工具卡片与普通文本混排时顺序正确、间距一致。
- [ ] [手] 工具卡片的折叠/展开可用键盘操作，状态有 `aria-expanded`。

## 7. 键盘交互

- [ ] [手] Enter 发送、Shift+Enter 换行，行为与 placeholder 描述一致。
- [ ] [自] 输入文本后按 Enter，出现 user 与 assistant 两类气泡。
- [ ] [手] Tab 焦点顺序：会话列表 → 消息区 → 输入框 → 发送按钮，顺序符合视觉顺序。
- [ ] [手] 所有可交互元素键盘可达，焦点环清晰可见（包括自绘按钮、抽屉开关、折叠按钮）。
- [ ] [手] Esc 关闭打开的弹层（侧栏抽屉、菜单、工具结果预览），焦点回到触发元素。
- [ ] [手] 弹层打开时焦点被限制在弹层内，关闭后不被困住。

## 8. 可访问性（WCAG 2.1 AA）

- [ ] [手] 正文与背景对比度 ≥ 4.5:1，大字 ≥ 3:1（用对比度工具抽查 muted 文本、状态色、按钮文字）。
- [ ] [手] 状态不只靠颜色区分，同时有文字/图标（已连接/未连接、成功/失败）。
- [ ] [自] 消息区有 `aria-live="polite"`，流式内容可被读屏软件播报。
- [ ] [手] 输入框有可读名称（`label` 或 `aria-label`），非仅 placeholder。
- [ ] [手] 所有按钮有可读名称（图标按钮需 `aria-label`）。
- [ ] [手] 焦点可见：键盘焦点有 ≥ 2px 高对比轮廓，不被 `outline: none` 抹掉。
- [ ] [手] 语义结构：使用 `<header>/<main>/<footer>` 或对应 landmark，标题层级不跳级。
- [ ] [手] 缩放 200% 时内容与控件不重叠、不丢失。

## 9. 视觉一致性

- [ ] [手] 间距：采用统一间距刻度（建议 4/8/12/16/24），同类元素间距一致。
- [ ] [手] 圆角：气泡、输入框、按钮、卡片圆角层级统一（如 8 / 12 / 14）。
- [ ] [手] 颜色层级：背景 / 面板 / 边框 / 文本 / 次要文本五级清晰，用户气泡与助手气泡可区分但不刺眼。
- [ ] [手] 字体：字号层级一致（标题 / 正文 / 辅助文字），中英文与代码字体分工明确。
- [ ] [手] hover / active / disabled 三态在所有按钮上表现一致。
- [ ] [手] 深色主题下无纯黑纯白硬对比，品牌色只用于强调，不滥用。
