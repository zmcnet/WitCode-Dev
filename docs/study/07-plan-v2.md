## 1. 你要的三件事，翻译成人话

| 你的话 | 落地成什么 |

| 工作方面，要 ZCode 的脑子与能力 | **工作循环**：想 → 动手 → 看结果 → 再想；带工具、上下文、会话 |

## 3. 插件长什么样

一个插件就是一个文件夹：

```
my-plugin/
├── plugin.json     # 我是谁、我要什么、我能提供什么
├── index.js        # 我的能力（服务端）
└── web/            # 我的界面（可选，浏览器里跑）
```

`plugin.json` 示例：

```json
{
  "name": "my-plugin",
  "version": "0.1.0",
  "description": "一个示例插件",
  "main": "index.js",
  "inject": ["tools", "models"],
  "provides": ["my-service"],
  "web": { "entry": "web/index.html" }
}
```

插件能做的事：

- 注册一个**工具**（让 Agent 能读写文件、跑命令）
- 注册一个**模型提供商**（OpenAI、Anthropic、本地模型）
- 注册一个**界面面板**（浏览器里的 iframe）
- 注册一个**命令**（斜杠命令）
- 监听**事件**（消息、工具调用、会话开始）

插件卸载时，它注册的东西**自动清理**，不留尾巴。

## 4. 三个阶段（先跑起来，再长本事）

### P0 骨架（1–2 周）：能聊天

- 插座板：注册、加载、事件、卸载
- 服务端：HTTP + WebSocket
- 浏览器：聊天界面，流式显示
- 一个假的模型插件（回声），证明链路通

**验收**：打开浏览器，输入一句话，看到流式回复。

### P1 手脚（2 周）：能干活

- 工作循环：想 → 调工具 → 看结果 → 再想
- 工具插件：读文件、写文件、列目录、搜索、跑命令
- 会话存储：SQLite，能恢复
- 真实模型：OpenAI 兼容接口

**验收**：让它读一个文件、改一行、再告诉你改了什么。

### P2 管家（2 周）：模型随便换

- 模型管家：提供商、模型目录、密钥
- 路由：按顺序、轮换、智能
- 失败兜底：一个不行换下一个
- 用量：每次请求花了多少 token、多少钱

**验收**：配两个提供商，第一个断开后自动切第二个，界面无感。

### P3 生态（2 周）：万物插件

- 插件安装/卸载/启停
- 界面插件：iframe 沙箱，能开自己的面板
- 主题：换色不重启
- 一个插件市场（静态 JSON）

**验收**：装一个第三方插件，它的面板出现在侧栏。

### P4 打磨（持续）

- 会话分享、导出
- 权限与确认
- 性能、稳定性
- 文档、示例插件

## 5. 技术选型（我定的，你可以否决）

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript | 前后端同一套类型，插件也好写 |
| 服务端 | Node.js + 原生 HTTP + ws | 轻，不引重框架 |
| 前端 | React + Vite | 生态最大，插件作者最容易上手 |
| 存储 | SQLite（会话）+ JSON（配置） | 单文件、好备份、零运维 |
| 插件隔离 | 服务端进程内（可信）+ 浏览器 iframe（第三方） | 先简单，后面可加 Worker |
| 包管理 | pnpm workspace | 一仓多包，插件好拆 |

## 7. 规矩（写给未来的我和子代理）

1. **内核不超过 1000 行**。内核一旦胖了，说明能力放错了地方。
2. **任何能力先问：能不能做成插件？** 能，就不进内核。
3. **插件卸载必须干净**。注册即返回清理函数，卸载时全部执行。
4. **前后端只通过 `protocol` 包通信**。不跨层 import。
5. **每个阶段必须有可运行的验收**。跑不起来不算完成。
6. **不复制三个参照项目的代码**。可以看设计、看交互，代码自己写。
